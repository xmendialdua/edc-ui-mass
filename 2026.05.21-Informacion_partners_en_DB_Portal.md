## 🎯 Introducción

El portal de Tractus-X (Catena-X) desplegado en el namespace `portal` mantiene un registro completo de todos los partners registrados en el espacio de datos, incluyendo:

- Información de compañías (empresas)
- Usuarios asociados a cada compañía
- Conectores EDC registrados por compañía
- Business Partner Numbers (BPN)

Esta documentación detalla cómo acceder y consultar esta información para implementar sistemas de autenticación y gestión de partners.

## 🔍 Consultas SQL Implementadas

### Consulta 1: Lista de Todos los Partners

**Objetivo**: Obtener lista completa de partners con información básica.

**SQL**:
```sql
SELECT 
    cu.email,
    cu.firstname,
    cu.lastname,
    c.name as company_name,
    c.business_partner_number as bpn
FROM portal.company_users cu
JOIN portal.identities i ON cu.id = i.id
JOIN portal.companies c ON i.company_id = c.id
WHERE cu.email IS NOT NULL
  AND c.business_partner_number IS NOT NULL
ORDER BY c.name;
```

**Explicación de JOINs**:

1. **company_users → identities** (`cu.id = i.id`):
   - Relación 1:1 porque `company_users.id` es PK y FK a identities
   - Obtenemos el `company_id` de la identity

2. **identities → companies** (`i.company_id = c.id`):
   - Relación N:1, muchas identities pueden pertenecer a una compañía
   - Obtenemos nombre y BPN de la compañía

**Campos WHERE**:
- `cu.email IS NOT NULL`: Filtrar usuarios sin email
- `c.business_partner_number IS NOT NULL`: Solo partners con BPN válido

**Resultado esperado**:
```
              email               |     firstname      | lastname |   company_name    |         bpn
----------------------------------+--------------------+----------+-------------------+----------------------
 dataspace@ikerlan.es             | Ikerlan            | S. Coop. | Ikerlan           | BPNL00000002IKLN
 dataspace@mondragon-assembly.com | Mondragon Assembly | S. Coop. | MondragonAssembly | BPNL00000000MASS
```

**Uso en Python/asyncpg**:
```python
query = """
    SELECT 
        cu.email,
        cu.firstname,
        cu.lastname,
        c.name as company_name,
        c.business_partner_number as bpn
    FROM portal.company_users cu
    JOIN portal.identities i ON cu.id = i.id
    JOIN portal.companies c ON i.company_id = c.id
    WHERE cu.email IS NOT NULL
      AND c.business_partner_number IS NOT NULL
    ORDER BY c.name
"""

rows = await conn.fetch(query)
for row in rows:
    print(row['email'], row['bpn'])
```

### Consulta 2: Validación de Login por Email

**Objetivo**: Buscar un partner específico por email para validar login.

**SQL**:
```sql
SELECT 
    cu.email,
    cu.firstname,
    cu.lastname,
    c.name as company_name,
    c.business_partner_number as bpn
FROM portal.company_users cu
JOIN portal.identities i ON cu.id = i.id
JOIN portal.companies c ON i.company_id = c.id
WHERE LOWER(cu.email) = LOWER($1)
  AND c.business_partner_number IS NOT NULL;
```

**Parámetros**:
- `$1`: Email del usuario (case-insensitive)

**Explicación**:
- Usa `LOWER()` para búsqueda case-insensitive
- Usa parámetro posicional `$1` para prevenir SQL injection
- Devuelve 0 o 1 resultado (email debería ser único)

**Ejemplo de ejecución en kubectl**:
```bash
kubectl exec -n portal portal-portal-backend-postgresql-0 -- \
  bash -c "PGPASSWORD=dbpasswordportal psql -U portal -d postgres -c \"
    SELECT cu.email, c.business_partner_number 
    FROM portal.company_users cu
    JOIN portal.identities i ON cu.id = i.id
    JOIN portal.companies c ON i.company_id = c.id
    WHERE LOWER(cu.email) = LOWER('dataspace@ikerlan.es');
  \""
```

**Resultado**:
```
       email        | business_partner_number
--------------------+-------------------------
 dataspace@ikerlan.es | BPNL00000002IKLN
```

**Uso en Python con parámetros**:
```python
query = """
```

### Consulta 3: Detalles Completos con Conector

**Objetivo**: Obtener información completa del partner incluyendo su conector EDC.

**SQL**:
```sql
SELECT 
    cu.email,
    cu.firstname,
    cu.lastname,
    c.name as company_name,
    c.business_partner_number as bpn,
    con.connector_url as dsp_url,
    con.name as connector_name,
    con.status_id as connector_status
FROM portal.company_users cu
JOIN portal.identities i ON cu.id = i.id
JOIN portal.companies c ON i.company_id = c.id
LEFT JOIN portal.connectors con ON con.provider_id = c.id
WHERE LOWER(cu.email) = LOWER($1)
  AND c.business_partner_number IS NOT NULL;
```

**Explicación de JOINs**:

1. **company_users → identities** (INNER JOIN):
   - Obtenemos la identity del usuario

2. **identities → companies** (INNER JOIN):
   - Obtenemos la compañía del usuario

3. **companies → connectors** (LEFT JOIN):
   - **LEFT JOIN** porque no todos los partners tienen conectores registrados
   - Un partner puede tener 0, 1 o múltiples conectores
   - Si hay múltiples conectores, se devuelven múltiples filas

**Campos adicionales**:
- `con.connector_url`: URL DSP del conector
- `con.name`: Nombre del conector
- `con.status_id`: Estado del conector (1=Active, etc.)

**Ejemplo de ejecución**:
```bash
kubectl exec -n portal portal-portal-backend-postgresql-0 -- \
  bash -c "PGPASSWORD=dbpasswordportal psql -U portal -d postgres -c \"
    SELECT 
        cu.email,
        c.name as company_name,
        c.business_partner_number as bpn,
        con.connector_url as dsp_url
    FROM portal.company_users cu
    JOIN portal.identities i ON cu.id = i.id
    JOIN portal.companies c ON i.company_id = c.id
    LEFT JOIN portal.connectors con ON con.provider_id = c.id
    WHERE LOWER(cu.email) = LOWER('dataspace@ikerlan.es');
  \""
```

**Resultado**:
```
       email        |   company_name    |         bpn          |                       dsp_url
--------------------+-------------------+----------------------+------------------------------------------------------
 dataspace@ikerlan.es | Ikerlan           | BPNL00000002IKLN     | https://edc-ikln-control.51.178.94.25.nip.io/api/v1/dsp
```

**Manejo de múltiples conectores**:

Si un partner tiene múltiples conectores:
```sql
-- Ejemplo: Partner con 2 conectores
 email            | bpn              | connector_url
------------------+------------------+-------------------
 user@company.com | BPNL00000001TEST | https://connector1.example.com/api/v1/dsp
 user@company.com | BPNL00000001TEST | https://connector2.example.com/api/v1/dsp
```

Para obtener solo un conector (el más reciente):
```sql
LEFT JOIN LATERAL (
    SELECT connector_url, name, status_id
    FROM portal.connectors
    WHERE provider_id = c.id
    ORDER BY date_last_changed DESC NULLS LAST
    LIMIT 1
) con ON true
```

## 💻 Implementación en Python

### Configuración de Conexión

**Dependencia requerida**: `asyncpg==0.30.0`

```python
import asyncpg

# Configuración de conexión
PORTAL_DB_CONFIG = {
    "host": "portal-portal-backend-postgresql.portal.svc.cluster.local",
```

```python
async def validate_partner_login(email: str):

                "company_name": row['company_name'],

    finally:
```

```python
async def get_partner_details(email: str):
    """Obtiene detalles completos del partner incluyendo conector."""
    conn = await get_db_connection()
    
    try:
        query = """
            SELECT 
                cu.email,
                cu.firstname,
                cu.lastname,
                c.name as company_name,
                c.business_partner_number as bpn,
                con.connector_url as dsp_url
            FROM portal.company_users cu
            JOIN portal.identities i ON cu.id = i.id
            JOIN portal.companies c ON i.company_id = c.id
            LEFT JOIN portal.connectors con ON con.provider_id = c.id
            WHERE LOWER(cu.email) = LOWER($1)
              AND c.business_partner_number IS NOT NULL
        """
        
        row = await conn.fetchrow(query, email)
        
        if not row:
            return None
        
        # Convertir DSP URL a Management URL
        dsp_url = row['dsp_url'] or ''
        management_url = dsp_url.replace("/api/v1/dsp", "/management")
        
        return {
            "email": row['email'],
            "firstname": row['firstname'] or '',
            "lastname": row['lastname'] or '',
            "company_name": row['company_name'],
            "bpn": row['bpn'],
            "dsp_url": dsp_url,
            "management_url": management_url
        }
        
    finally:
        await conn.close()
```

### Función: Convertir DSP URL a Management URL

```python
def convert_dsp_to_management_url(dsp_url: str) -> str:
    """
    Convierte URL DSP del conector a URL Management API.
    
    Ejemplo:
        Input:  https://edc-ikln-control.51.178.94.25.nip.io/api/v1/dsp
        Output: https://edc-ikln-control.51.178.94.25.nip.io/management
    """
    if not dsp_url:
        return ""
    
    # Remover sufijo /api/v1/dsp y añadir /management
    base_url = dsp_url.replace("/api/v1/dsp", "")
    return f"{base_url}/management"
```

**Uso**:
```python
dsp = "https://edc-ikln-control.51.178.94.25.nip.io/api/v1/dsp"
mgmt = convert_dsp_to_management_url(dsp)
print(mgmt)
# Output: https://edc-ikln-control.51.178.94.25.nip.io/management
```

## 🔐 Consideraciones de Seguridad

### 1. Conexión a Base de Datos

**Recomendaciones**:
- ✅ Usar connection pooling en producción (asyncpg pool)
- ✅ No exponer credenciales en código (usar secrets)
- ✅ Conexión interna al cluster (no exponer puerto públicamente)

**Ejemplo con pool**:
```python
import asyncpg

# Crear pool de conexiones
pool = await asyncpg.create_pool(
    host="portal-portal-backend-postgresql.portal.svc.cluster.local",
    port=5432,
    database="postgres",
    user="portal",
    password="dbpasswordportal",
    min_size=2,
    max_size=10
)

# Usar conexión del pool
async with pool.acquire() as conn:
    rows = await conn.fetch(query)
```

### 2. Queries Parametrizadas

**Siempre usar parámetros posicionales** para prevenir SQL injection:

```python
# ✅ CORRECTO
query = "SELECT * FROM portal.company_users WHERE email = $1"
result = await conn.fetchrow(query, user_email)

# ❌ INCORRECTO (vulnerable a SQL injection)
query = f"SELECT * FROM portal.company_users WHERE email = '{user_email}'"
result = await conn.fetch(query)
```

### Diagrama de Relaciones Principales

```
┌─────────────────┐
│   companies     │
│  (partners)     │
└────────┬────────┘
         │ 1
         │
         │ N
┌────────┴────────┐
│   identities    │
│  (base users)   │
└────────┬────────┘
         │ 1
         │
         │ 1
┌────────┴────────────┐
│   company_users     │
│  (human users)      │
└─────────────────────┘


┌─────────────────┐
│   companies     │ 1
└────────┬────────┘
         │
         │ N
┌────────┴────────┐
│   connectors    │
│  (EDC nodes)    │
└─────────────────┘
```

### Cardinalidad

- **companies** 1:N **identities** (una compañía tiene muchos usuarios)
- **identities** 1:1 **company_users** (extensión para usuarios humanos)
- **companies** 1:N **connectors** (una compañía puede tener múltiples conectores)
